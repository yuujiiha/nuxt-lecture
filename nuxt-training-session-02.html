Two Kinds of Rules

Nuxtが決めること／チームが決めること

Nuxtの規約

配置による「動作」を決める

  • pages/users.vue → /users
  • components/UserCard.vue → 自動import
チームの規約

コードの「分け方」を決める

  • ページはどこまで担当するか
  • いつコンポーネントへ分けるか
  • データとイベントをどう渡すか

配置で動作が決まり、分け方で保守しやすさが決まる。

今回は両方を扱う3 / 10
Responsibility of pages/

pages は
画面の「指揮者」

担当すること

  • URLに対応する画面の入口
  • route params・query・ページメタ情報
  • 画面単位のデータ取得を始める
  • 複数コンポーネントを組み合わせる

詳細なUIや共通ロジックを抱え込みすぎない。

// pages/users/[id].vue
<script setup lang="ts">
definePageMeta({
  middleware: 'auth',
})

const route = useRoute()
const { data: user } = await useFetch(
  `/api/users/${route.params.id}`,
)
</script>

<template>
  <UserProfile :user="user" />
</template>
Page = URLと画面全体の文脈を知る4 / 10
Responsibility of components/

components は
意味のある「UI部品」

基本の担当

  • propsで表示データを受け取る
  • emitで操作を親へ伝える
  • 開閉など、そのUIだけの状態を持つ
  • ひとつの明確なUI責務を持つ
// components/UserProfile.vue
<script setup lang="ts">
const props = defineProps<{
  user: User
}>()

const emit = defineEmits<{
  edit: [id: string]
}>()
</script>

名前は見た目より役割で

UserCard ○　WhiteBox ×

BaseButton：汎用UI
AppHeader：アプリ共通
UserProfile：機能UI

Takeaways

今日の3つの規約

pagesは、URLと画面全体の文脈を担当する。

componentsは、名前で説明できるUI責務を担当する。

データはpropsで下へ、操作はemitで上へ伝える。
