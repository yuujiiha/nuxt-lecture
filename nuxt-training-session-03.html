チームの規約

依存する仕組みで分類する

composables：Vue・Nuxtに依存

utils：原則として依存しない

「共通処理」という理由だけで選ばない。

The Core Difference

同じ「関数」でも、性質が違う

utils

入力を受け取り、結果を返す

状態を持たず、Vue・Nuxtを知らない。

formatPrice(1000)
→ "1,000円"
↔
composables

状態やライフサイクルを扱う

Vue・Nuxtの機能を組み合わせて返す。

const { page, next } =
  usePagination()

計算・変換ならutils。リアクティブな状態やNuxtの文脈が必要ならcomposable。

Responsibility of utils/

utils は
小さく純粋な処理

基本の規約

  • 必要な値は引数で受け取る
  • 結果は戻り値として返す
  • refやuseRouteを使わない
  • 同じ入力なら同じ結果になる

単体テストがしやすく、Vue以外からも利用できる。

// utils/formatPrice.ts
export const formatPrice = (
  price: number,
): string => {
  return `${price.toLocaleString()}円`
}

// utils/isValidEmail.ts
export const isValidEmail = (
  value: string,
): boolean => {
  return EMAIL_PATTERN.test(value)
}
命名：formatXxx / isXxx / calculateXxx5 / 10
Responsibility of composables/

composables は
リアクティブな振る舞い

使うサイン

  • ref・computed・watch
  • onMountedなどのライフサイクル
  • useRoute・useStateなどのNuxt機能
  • 複数のcomposableを組み合わせる
// composables/usePagination.ts
export const usePagination = () => {
  const page = ref(1)

  const next = () => page.value++
  const reset = () => { page.value = 1 }

  return {
    page: readonly(page),
    next,
    reset,
  }
}

命名：useXxx

状態：関数の中で作る。アプリ全体で共有する場合はuseStateを使う。

module直下のrefはSSRで共有される恐れがある6 / 10

Takeaways

今日の3つの規約

Vue・Nuxtに依存しない計算・変換・判定はutilsへ置く。

リアクティブな状態やライフサイクルを扱う処理はcomposablesへ置く。

短い処理は無理に共通化せず、責務が見えてから切り出す。
