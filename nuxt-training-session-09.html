Reactive Performance

リアクティブ処理を
増やしすぎない

基本規約

  • 導出値はcomputed
  • watchの対象を明示する
  • listの:keyは安定したID
  • 大きな外部objectは深くreactiveにしない

避けたいkey

<li
  v-for="(item, index) in items"
  :key="index"
>

並び替え・追加時にDOMの対応が崩れやすい。

安定したkey

<li
  v-for="item in items"
  :key="item.id"
>
再描画を恐れるより、不要な依存を作らない5 / 10

SEO & Metadata

ページごとに
意味を伝える

最低限の規約

  • ページ固有のtitle・description
  • 内容を表すh1を原則ひとつ
  • 見出し階層を順序どおりにする
  • リンク文言だけで遷移先が分かる

SNS共有が重要ならogTitle・ogDescription・ogImageも設計する。

const { data: article } = await useFetch(
  `/api/articles/${route.params.slug}`,
)

useSeoMeta({
  title: () => article.value?.title,
  description: () =>
    article.value?.description,
  ogTitle: () => article.value?.title,
  ogDescription: () =>
    article.value?.description,
})
検索エンジンだけでなく、共有時と利用者にも役立つ7 / 10
