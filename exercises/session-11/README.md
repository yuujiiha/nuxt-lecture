# #11 エラーの読み方とデバッグ — 演習

この演習には、わざと壊してあるページが3つあります。
エラーを読んで原因を見つけ、正しく表示されるように直してください。

## ルール

- **AIは使わない**でください。検索して調べるのはOKです。
- いきなりコードを書き換えずに、まず **「どこに」「何と」書かれているか** を読みます。
- 直したら、下の「報告テンプレート」を埋めてください。直せなかった場合も、どこまで分かったかを書けば十分です。

## エラーが出る場所は3つある

| 場所 | 開き方 | 主に出るもの |
|---|---|---|
| ブラウザの画面 | そのまま見る | エラーページ、表示崩れ |
| ブラウザの DevTools | `F12`（Mac は `Cmd + Option + I`）→ **Console** タブ・**Network** タブ | ブラウザで起きたエラー・警告、通信の結果 |
| ターミナル | StackBlitz の画面下部（ローカルでは `npm run dev` を実行した画面） | サーバー側で起きたエラー・警告 |

Nuxt では、ページを最初に開いたときの処理は **サーバー** で動き、ボタンを押したあとなどの処理は **ブラウザ** で動きます。
そのため、エラーはどちらか片方にしか出ないことがあります。

## 演習1：プロフィールが表示されない

- **症状**：`/exercise-1` を開くと、プロフィールカードが表示されない。エラーページにはならない。
- **ゴール**：「山田 花子」のカードが表示される。

<details>
<summary>ヒント1</summary>

画面にはエラーが出ていません。Console タブかターミナルに **警告（warn）** が出ていないか見てみましょう。

</details>

<details>
<summary>ヒント2</summary>

警告に出ている名前と、`app/components/` にあるファイル名を1文字ずつ比べてみましょう。

</details>

## 演習2：メンバー一覧を開くとエラー画面になる

- **症状**：`/exercise-2` を開くと、500 エラーの画面になる。
- **ゴール**：4人全員が表示される。住所が登録されていない人には「未登録」と表示する。

<details>
<summary>ヒント1</summary>

エラーメッセージの `(reading 'city')` は「`city` を読み取ろうとしたけれど、その手前が `undefined` だった」という意味です。
では、`city` の手前にあるのは何でしょうか？

</details>

<details>
<summary>ヒント2</summary>

ブラウザで `/api/members` を直接開き、返ってくるデータを1件ずつ確認してみましょう。

</details>

<details>
<summary>ヒント3</summary>

`exercise-2.vue` の `type Member` には「全員が `address` を持っている」と書かれています。この型は、実際のデータと合っていますか？

</details>

## 演習3：ボタンを押しても商品が出てこない

- **症状**：`/exercise-3` で「商品を読み込む」を押しても、何も表示されない。
- **ゴール**：ボタンを押すと、商品が3件表示される。

<details>
<summary>ヒント1</summary>

ボタンを押す処理はブラウザで動きます。Console タブを開いた状態で、もう一度ボタンを押してみましょう。

</details>

<details>
<summary>ヒント2</summary>

Network タブを開いた状態でボタンを押し、リクエストの URL とステータスコードを確認しましょう。

</details>

<details>
<summary>ヒント3</summary>

`server/api/` にあるファイル名と、`$fetch` に書いた URL を比べてみましょう。

</details>
