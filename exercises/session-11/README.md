# #11 エラーの読み方とデバッグ — 演習

この演習には、わざと壊してあるページが3つあります。
エラーを読んで原因を見つけ、正しく表示されるように直してください。

## ルール

- **AIは使わない**でください。検索して調べるのはOKです。
- いきなりコードを書き換えずに、まず **「どこに」「何と」書かれているか** を読みます。
- 直したら、下の「報告テンプレート」を埋めてください。直せなかった場合も、どこまで分かったかを書けば十分です。

## エラーが出る場所は3つある

| 場所 | 開き方 | 主に出るもの |
|---|---|---|
| ブラウザの画面 | そのまま見る | エラーページ、表示崩れ |
| ブラウザの DevTools | `F12`（Mac は `Cmd + Option + I`）→ **Console** タブ・**Network** タブ | ブラウザで起きたエラー・警告、通信の結果 |
| ターミナル | StackBlitz の画面下部（ローカルでは `npm run dev` を実行した画面） | サーバー側で起きたエラー・警告 |

### StackBlitz では、プレビューを別タブで開く

StackBlitz の画面のまま DevTools を開くと、StackBlitz 自体のログと演習アプリのログが混ざって表示されます。
プレビュー上部の **「新しいタブで開く」ボタン** を押し、演習アプリだけを別タブで開いてから、そのタブで DevTools を開いてください。

- ブラウザ側のエラー → **新しいタブ** の DevTools
- サーバー側のエラー → **元の StackBlitz タブ** のターミナル

### 同じページでも、開き方で処理が動く場所が変わる

| 開き方 | 処理が動く場所 | エラーが出る場所 |
|---|---|---|
| URL を直接開く・リロードする | **サーバー** | ターミナル（画面はエラーページ） |
| リンクで移動する・ボタンを押す | **ブラウザ** | DevTools の Console |

そのため、エラーはどちらか片方にしか出ないことがあります。「ターミナルに何も出ていない」ときは Console を、「Console に何も出ていない」ときはターミナルを見てください。

## 演習2：メンバー一覧を開くとエラー画面になる

- **症状**：`/exercise-2` を開くと、エラーの画面になる。
- **ゴール**：4人全員が表示される。住所が登録されていない人には「未登録」と表示する。

直す前に、次の2通りで開いて、**エラーがどこに出るか** を比べてください。

1. 演習一覧のリンクから `/exercise-2` に移動する → Console とターミナルを見る
2. `/exercise-2` を開いた状態でリロードする → Console とターミナルを見る

報告テンプレートには、この2つで何が違ったかも書いてください。
